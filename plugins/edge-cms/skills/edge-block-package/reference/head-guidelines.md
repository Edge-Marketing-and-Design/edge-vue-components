# Head JSON guidelines

Head JSON declares structured head entries consumed by Hub preview and the
public renderer. It is JSON, not HTML. The supported top-level collections used
by the current CMS are `link`, `style`, `script`, and `meta`.

## When a site already has Head JSON

Export and preserve it. Add only missing dependencies, deduplicate equivalent
entries, and verify that removing or consolidating a URL will not affect other
blocks or pages.

## When a site has no Head JSON

Use `defaults/head-empty.json` when no external resource is needed. System-font
sites can leave every array empty. Add font resources only when the selected
theme actually references those families.

For Google Fonts, use structured link entries:

```json
{
  "link": [
    {
      "rel": "preconnect",
      "href": "https://fonts.googleapis.com"
    },
    {
      "rel": "preconnect",
      "href": "https://fonts.gstatic.com",
      "crossorigin": ""
    },
    {
      "rel": "stylesheet",
      "href": "https://fonts.googleapis.com/css2?family=Poppins:wght@400;500;600;700&display=swap"
    }
  ]
}
```

The root `head.json` in this kit loads the three M4RL families: Poppins, Noto
Sans Devanagari, and Playfair Display.

## Rules

- Use HTTPS URLs.
- Preconnect only to origins actually used.
- Include `crossorigin: ""` for cross-origin font asset origins such as
  `fonts.gstatic.com`.
- Request only weights and styles used by the design.
- Keep font family spelling consistent with Theme JSON.
- Prefer one consolidated provider stylesheet over duplicate requests.
- Confirm licensing and production use for every font.
- Treat scripts as exceptional. Document their owner, purpose, privacy impact,
  load behavior, and failure mode before adding them.

## Uploaded fonts

The CMS may store uploaded font faces as structured `style` entries containing
`children` and `innerHTML` with matching `@font-face` CSS. Preserve the exact
shape generated by the current Hub font workflow. Do not fabricate storage URLs
or credentials.

## What does not belong in Head JSON

- raw `<link>`, `<style>`, `<script>`, or `<meta>` strings;
- CSS `@import` statements;
- general page styling that belongs in Theme JSON or Extra CSS;
- block markup;
- analytics or tracking scripts without explicit authorization;
- secret keys or authenticated URLs.

## Validation and acceptance

Valid JSON only proves structure. Before production use, verify provider URLs,
font loading, requested weights, Content Security Policy compatibility, privacy
requirements, browser rendering, and fallbacks. Missing Head JSON is acceptable
when the theme uses only system fonts.
